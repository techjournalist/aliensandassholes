# Endless mode, difficulty tiers and daily run (design notes)

Status: designed in chat, not built (sections 1 to 7). Read this before starting any of it.
Written 2026-10-01 after Levels 9 and 10 shipped on branch
`graphics-pass-units-tiers`.

## Why this exists
The user asked what else would improve the game and liked "difficulty and
replay options". They are also thinking about hosting on itch.io or Steam, so
the design leaves room for a real leaderboard and achievements later.

## 1. Difficulty tiers (build first)
**Built** (AGENTS.md P3-D1). The numbers below are the first draft; it lost
every seeded bot run. Shipped Bramble: hp x1.05, speed x1, gold x1, 16 lives,
bounty x0.95. Save format as planned (`bramble: { stars, bestLives }`, still
`v: 1`).

- **Meadow**: exactly today's difficulty. Nothing changes.
- **Bramble**: the harder tier. Starting numbers, to be tuned with bots:
  - enemy hp x1.25, enemy speed x1.10
  - starting gold x0.85, starting lives 15 (Meadow is 20)
  - kill bounty x0.90
  - waves and maps unchanged
- Optional later: **Cozy**, an easier tier. Not planned yet.
- Stars are stored per tier. The world map shows a thorn mark on a level
  beaten on Bramble.
- The tier is picked on the world map next to the Play button and remembered.
- Save format: `bb-progress` is `{ v: 1, levels: { id: { unlocked, stars,
  bestLives } } }`. Add `bramble: { stars, bestLives }` per level and keep
  `v: 1` readable (fill missing fields the way `Progress.load` already does).
- Implementation idea: a `difficulty` multiplier table read in
  `GameState.loadLevel` and `spawnEnemy`/bounty code. Do not edit level files.
- Balance gate: Meadow margins are already thin on several levels. Run
  `scratchpad/l4bot.js`-style isolated bot runs (10 or more per level) and
  tune the multipliers until Bramble is hard but beatable. Bots are weaker than
  people, so aim for roughly 50 to 70 percent bot wins, not 100.

## 2. Endless mode (build second)
Unlocks after Level 10 is won. The player picks any of the 10 maps.

- **Waves 1 to 13** use the level's own handmade waves (boss on 13).
- **Wave 14 onward** are generated by a pure function in `GameState`
  (no rendering, no `Math.random`, seeded RNG):
  - a budget that grows each wave, spent on grunts, tricksters, trolls and bats
    using each type's cost weight;
  - each wave picks which roads to use, weighted toward roads not used last
    wave, so divergent maps (Levels 4, 6 to 10) stay tense;
  - a boss every 5th wave, cycling through the bosses already in
    `ENEMY_TYPES` (shadow-crow, tideworm, matriarch, rime, ashen, leafstorm,
    gloam, heartbloom);
  - flyers must always have anti-air coverage possible, so never send a flying
    group on a road with no buildable tile in anti-air range.
- **Scaling**: `hpScale` keeps climbing past 13 (today it is
  `1 + (wave - 1) * 0.05`). Consider a steeper slope after 13 and a hard cap on
  enemies alive at once so phones do not choke. Measure draw calls at the cap.
- **Lives** do not refill. A short breather every 5 waves (longer prep timer).
- **No win screen.** The run ends when the Bastion falls. The end screen shows
  waves survived, kills, gold earned and the best so far.
- **Per-map best** is saved and shown on the world-map node.
- UI: wave counter reads "Wave 14" with no "of N". Boss intro banner and camera
  push already work for any `e.boss`.
- Music: the boss mix already follows `e.boss`; no change needed.

## 3. Daily run
- Seed = the UTC date (for example `2026-10-02`). The seed also picks the map
  and the difficulty tier for that day, so everyone gets the same run with no
  server.
- Needs repeatable randomness. Today the game uses unseeded `Math.random` for
  enemy lane jitter and a few effects. Replace the gameplay uses with a seeded
  generator (renderer effects already use their own `fxRand`). This also fixes
  the Level 6 flaky bot test, so do it as its own step first.
- Without accounts, store the best wave per day and a day streak in
  `localStorage` (new key, for example `bb-daily`). Clearing site data resets it.
- A "Copy result" button writes a short text such as
  `Briar & Bastion Daily 2 Oct: wave 24 on The Keep Between`.
- Honest limit: same waves, but fights are not identical unless every random
  call is seeded.

## 4. Hosting notes (itch.io and Steam)
Check each point against current platform docs before relying on it.

- **three.js is loaded from a CDN** (`cdnjs`, r128). A packaged or offline build
  must ship `three.min.js` locally. `scratchpad/three.min.js` is a copy of r128.
  The no-build rule still holds: a plain `<script src="js/three.min.js">`.
- **itch.io**: an HTML5 game is a zip with `index.html` at the root plus the
  `js/` folder, played in an iframe. `localStorage` should work but is per
  browser. Test audio start (needs a click, already handled) and fullscreen.
- **Steam**: needs a desktop wrapper (Electron or Tauri). Capacitor (named in
  `AGENTS.md`) is for iOS and Android. Steamworks adds real **leaderboards**,
  **achievements** and **cloud saves**, which would replace the copy-result
  button and the local-only streak. Keep a thin "platform" layer so score
  submission and achievements are one function each, with a local fallback.
- Leaderboard design if it happens: submit (map, tier, wave reached, date seed)
  per run. Daily runs get one board per day. The server, not the client, should
  be the judge of anything that matters, since a score from a client can be
  faked.
- Possible achievements: first win on each level, beat Bramble on a level, reach
  wave 25 in Endless, no-leak boss kill, one tower type only win.
- Phone controls and frame rate on real devices are still unmeasured.

## 5. Suggested build order
1. Seeded gameplay randomness (also stabilizes the test harness).
2. Difficulty tiers (Meadow and Bramble) with the bot tuning gate.
3. Endless mode on one map first (Level 9 or 4), then all maps.
4. Daily run and copy-result.
5. Platform layer, then itch.io packaging, then Steam wrapper if wanted.

## 6. Tests to add
- Wave generator: same seed gives the same waves; flyers never land on a road
  with no anti-air tile; enemy count never exceeds the cap.
- Difficulty: Meadow numbers are unchanged (a seeded run reproduces today's
  lives, gold and kills); Bramble multipliers apply to hp, speed, gold, lives
  and bounty.
- Save format: old `bb-progress` saves still load.
- Endless end screen appears on loss, never a win screen.

## 7. New enemy types (design notes, not built)
Idea from the user, 2026-10-01: the roster is the same four enemies (grunt,
trickster, troll, bat) across all 10 levels and only the boss changes. New
enemies would change how the player plays, not just where they build. Each
asks for a different tower answer, which supports the "no dominant strategy"
rule in `AGENTS.md`.

Candidates:
- **Spore-Medic**: small mushroom healer, mends enemies near it. Forces focus
  fire. Rewards long-range and single-target towers.
- **Sapper**: goblin that jams the nearest tower for a few seconds. Forces
  clustered towers or killing it first.
- **Digger**: mole that burrows under part of the road and cannot be targeted
  while underground, so it can skip the chokepoint. Hardest to build because
  it touches targeting and road logic.

Considered and dropped by the user (2026-10-01): the **Pod-Bearer** (splits
into sprouts on death) and the **Magpie** (steals gold on a leak). Do not
build them unless the user brings them back.

Where to use them:
- Leave Levels 1 to 7 alone (played and tuned). Introduce one new type each in
  Levels 8, 9 and 10 (three types: Medic, Sapper, Digger), with a short first-appearance tip. The four existing
  enemies stay in every level.
- Add them to the Endless wave generator's pool (section 2) so late waves are
  more varied than the same four types.
- Add them to Bramble (section 1) later if more variety is wanted.

Cost per enemy, roughly 1 to 3 hours, mostly tuning:
- a model and animation (the per-limb rig in `renderer.js` covers walkers; a
  new silhouette needs its own recipe and pivots, like the boss recipes);
- new logic in `GameState` (heal aura, burrow state, tower jam), plus `ENEMY_TYPES` stats;
- a sound and a first-appearance tip;
- balance: isolated bot runs (10 or more) on every level that gets the type.

Suggested order: Spore-Medic first (simplest, one new rule), then the Sapper,
then the Digger last (it touches targeting and road logic). Each forces a
different tower choice.

Watch out for:
- Flyer rule: only the Druid and Artillery hit flyers. Do not make any new
  enemy both fast and unreachable for them.
- The bot in `scratchpad/l4bot.js` picks towers blindly, so a new type that
  needs a specific tower will look harder to the bot than to a person. Add
  counters to the bot's plan before judging balance.
- Leaks cost 1 life for normal enemies and 5 for bosses. Decide the cost for
  any new type explicitly (likely 1 for all three).
